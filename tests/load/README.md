# 本地素材上传模拟压测

运行原始工作台的 HTTP API，通过独立 Mock 执行“扫描 → 获取源 URL → CreateAsset → 模拟拉取和处理 → 轮询至 Active → 持久化”。不修改生产代码、不读取正式通道或令牌，不连接外部平台。调度器、工作台、Mock 分别运行在独立进程中，服务仅绑定 `127.0.0.1` 随机端口。

## 运行

在项目根目录执行，要求 Node.js 18+、已安装项目依赖：

```powershell
npm run load:local
npm run load:local -- --quick
npm run load:local -- --only scale-10k
npm run load:local -- --only scale-10k-no-flush
npm run load:local -- --no-profile
```

也可以使用内置运行时：

```powershell
.\runtime\node.exe tests/load/run.mjs
```

默认一轮约 6–8 分钟；机器性能、调度和文件系统负载会影响时间。控制台每 10 秒输出进度，每完成一个场景就更新报告。任何数量、类型、状态或计数校验失败，立即停止后续场景并返回非零退出码。Ctrl+C 终止本轮启动的子进程，不操作已有服务。

## 默认场景

| ID | 素材数 | 并发 | 轮询 ms | 模拟处理 ms | 目的 |
| --- | ---: | ---: | ---: | ---: | --- |
| c1 / c3 / c5 / c10 / c20 | 并发 × 6 | 1 / 3 / 5 / 10 / 20 | 3000 | 100 | 默认轮询下的并发阶梯 |
| fast-poll | 120 | 20 | 250 | 100 | 与 c20 比较轮询等待 |
| slow-processing | 120 | 20 | 250 | 1000 | 检查模拟处理变慢时的行为 |
| scale-1k | 1000 | 20 | 250 | 100 | 千级基线 |
| scale-10k | 10000 | 20 | 250 | 100 | 万级任务、正常持久化、CPU 采样 |
| scale-10k-no-flush | 10000 | 20 | 250 | 100 | 仅在测量期间关闭 flush 的诊断对照、CPU 采样 |

每个场景使用新进程、独立目录、4 个组、唯一名称和 1 KiB 内存占位素材，Image/Video/Audio 类型均匀分布。Mock 使用递增 ID，避免原测试夹具的短随机 ID 在大样本中发生碰撞；Mock 读取完整响应体，但不进行格式解码、转码或审核。快速验证只运行两组 20 个素材，用来验证脚本和落盘对照逻辑。

## 测量和校验

- CPU、内存、事件循环、HTTP 与 flush 指标：从开始扫描到迁移完成。CPU 按单核 100% 计算；内存每 250ms 采样，不能视为连续峰值。
- 完成吞吐：`成功数 / 迁移阶段秒数`，包含工作槽最后收尾的时间，不包含初始化、造数、扫描与报告生成。扫描耗时单列。CPU 采样场景会有额外开销。
- 素材服务时间：从 worker 领取到最终状态，包含获取 URL、提交、等待处理、轮询，不含队列等待。`pollResidenceMs` 为其中的轮询阶段时间。
- HTTP：工作台内部采集各上游 Action 的客户端延迟；Mock 采集服务端延迟；调度器定期读取任务列表，单独统计控制台 API 的客户端延迟。时间均使用单调时钟，百分位使用 nearest-rank。
- flush：对 `engine.flush` 外包计时，覆盖全量 JSON 序列化和同步文件写入/改名，不能直接等同于纯磁盘写入耗时。
- 正确性：全部素材完成、无失败/跳过/在途；目标数量与源相等、名称唯一、类型匹配且全部 Active；CreateAsset 和 Mock 完成数量匹配；最终任务文件计数一致。
- 关闭 flush 的场景仅用于归因。测量结束后调用原始 flush 生成最终任务文件，补写耗时不计入该诊断场景。正式配置不提供“关闭持久化”开关。

## 输出

每次运行在 `reports/local-load/<UTC时间戳>-<进程ID>/` 生成独立目录（Git 忽略）：

- `report.html`：离线图表与结果表。
- `report.md`：完整口径、指标、对照结论和优化建议。
- `results.json`：环境、场景参数、校验、分项延迟、资源时间序列和 CPU 热点。
- `results.csv`：场景汇总。
- `*.cpuprofile`：万级场景 CPU 采样，可导入 DevTools Performance。
- `.work/`：各场景的通道配置和最终任务文件，均为本地模拟数据，保留便于复核。

这是一轮短时探索性压测，不是长期稳定容量评估。每个场景仅测一次；运行顺序、其他进程、JIT、操作系统调度与文件缓存均可能影响对照。对噪声范围内的小差异应复跑确认。脚本不注入故障，也不模拟真实公网、大文件、转码和审核；结果不能替代真实平台压测。
